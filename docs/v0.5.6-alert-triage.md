# V0.5.6 — Alert Triage

La V0.5.6 transforme la liste d’alertes du workspace en véritable boîte de veille exploitable, sans modifier le modèle de scoring `intelligence-v0.5.5`.

## Boîte d’alertes

- Les alertes non lues sont affichées en priorité.
- Le compteur du dashboard est calculé sur toutes les alertes non lues du workspace, et non plus seulement sur la fenêtre chargée à l’écran.
- Le corps de l’alerte est visible directement dans la liste, notamment les garde-fous `veille uniquement` issus de la V0.5.5.
- Une alerte peut être marquée comme lue ou archivée.
- Une action permet de marquer toutes les alertes actives comme lues.
- Les alertes archivées sortent de la boîte active afin de ne pas polluer la veille courante.

## Sécurité et isolation

Toutes les mutations vérifient l’appartenance de l’utilisateur au workspace de l’alerte directement dans la requête SQL. Un identifiant d’alerte seul ne permet donc pas de modifier une alerte appartenant à un autre workspace.

Les previews Vercel restent en lecture seule via la politique existante `canWriteRuntimeState()`.

## Versioning

- Engine / application : `0.5.6`
- Modèle de score : reste `intelligence-v0.5.5`, car la formule de scoring n’est pas modifiée par cette release UX/veille.

Aucune migration Neon n’est nécessaire : les colonnes `status` et `read_at` existaient déjà dans la table `alerts`.
