# V0.5.9 — Runtime hardening

La V0.5.9 ne modifie ni les règles métier ni le modèle de score. Elle rend les builds et les déploiements plus reproductibles.

## Node.js

Le projet exige désormais **Node 24.x** au lieu de `>=22.0.0`.

- Vercel ne peut plus basculer automatiquement vers une future version majeure de Node ;
- GitHub Actions utilise Node 24 ;
- `.nvmrc` aligne les environnements de développement locaux.

## Dépendances npm

Un `package-lock.json` lockfileVersion 3 est désormais versionné. Il a été généré par GitHub Actions avec Node 24 / npm 11 à partir du `package.json` V0.5.9.

La CI installe les dépendances avec `npm ci` et le cache npm au lieu de refaire une résolution libre via `npm install`.

Conséquence : deux builds d’un même commit réutilisent le même arbre de dépendances transitives.

## Neon Auth / Better Auth

`@neondatabase/auth` reste volontairement figé sur `0.5.0-beta`.

L’audit a confirmé un warning npm upstream dans l’UI transitive embarquée par Neon Auth : `@daveyplate/better-auth-ui` utilise une version de `better-call` différente de celle attendue par un plugin Better Auth résolu dans l’arbre.

Aucun `--legacy-peer-deps` ni override forcé n’est conservé : l’application utilise la pile actuellement validée en production, simplement verrouillée par le lockfile. Une correction de cette divergence doit venir d’une version compatible de la chaîne Neon Auth / auth-ui, puis être testée explicitement avant upgrade.

## Vercel previews

Les branches `feature/*`, `feat/*`, `fix/*` et `chore/*` n’ouvrent plus de preview Vercel. La validation de branche est assurée par GitHub CI ; `main` reste la voie de déploiement production.

Cela évite les tentatives de provisioning inutiles observées sur les branches `feat/*` et réduit la consommation de ressources Vercel.

## Score

Le modèle de score reste `intelligence-v0.5.5`. Seule la version application / moteur passe en `0.5.9`.
