# V0.5.5 — Policy-aware Monitoring

La V0.5.5 propage les garde-fous de décision commerciale jusque dans la veille automatique.

## Changement de politique RNE

Le moteur compare désormais le fait `commercial_prospecting_allowed` entre deux observations. Une transition explicitement observée entre `allowed` et `blocked` produit un événement `COMMERCIAL_REUSE_CHANGE` dédié.

Une valeur absente n’est jamais interprétée comme un changement de politique : cela évite qu’une indisponibilité temporaire de l’INPI/RNE génère une fausse alerte. L’état `unknown` reste néanmoins fail-closed pour les actions commerciales tant que le statut n’est pas confirmé.

Le changement de politique est important pour la veille, mais ne contribue pas au Momentum commercial : une évolution du cadre de réutilisation n’est pas un signal de croissance ou d’intention d’achat.

## Alertes de veille

Les événements opérationnels restent visibles quelle que soit la politique RNE : ouverture d’établissement, attribution BOAMP, changement de gouvernance, évolution financière, etc.

- **allowed** : l’alerte conserve son titre et son contenu métier.
- **blocked** : l’alerte est explicitement présentée comme une information de veille et rappelle qu’aucune sollicitation ni enrichissement de contacts ne doit être déclenché.
- **unknown** : comportement fail-closed identique jusqu’à confirmation du statut, sans fabriquer d’événement réglementaire depuis une donnée absente.

Un changement observé vers `blocked` est une alerte de sévérité élevée ; une levée d’opposition reste signalée avec une sévérité moyenne.

Aucun changement de schéma de base de données n’est requis : le type d’alerte reste un champ texte et les alertes utilisent le modèle existant.
